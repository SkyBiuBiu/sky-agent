# Sky Agent

Sky Agent 是一个多 Agent 协同站点：把一个需求交给一支虚拟软件团队，团队中的产品经理、架构师与工程师通过共享消息池发布与订阅消息，按固定的 SOP 顺序协作，最终产出 PRD、系统设计和可直接运行的网页代码。

每个 Agent 只订阅自己关心的消息类型，按顺序执行并把自己的产出发布回共享消息池；上游产出即下游输入，因此过程可观察、产物可追溯。模型调用使用用户自己填写的 OpenAI 兼容接口，不依赖平台内置模型。

## 功能一览

### 1. 工作台输入需求

在工作台输入一句话需求即可启动团队（例如「做一个待办清单网页 demo」）。输入框下方展示当前 SOP 流水线，任务运行期间可随时点击「停止任务」中断。

![工作台输入需求示意图](docs/images/home-requirement-input.png)

### 2. 模型配置

填写 Base URL、模型名和 API Key，支持连通性测试。Key 只保存在服务端，页面与日志中只出现脱敏后的值。

![模型配置示意图](docs/images/model-config.png)

### 3. SOP 协作流程

默认三个角色按顺序执行：产品经理（PRD）→ 架构师（系统设计）→ 工程师（代码）。流水线节点会实时标记当前执行到的角色与状态。

![SOP 协作流程示意图](docs/images/collaboration-process.png)

### 4. 共享消息池

采用发布/订阅机制，以时间线展示每条消息的发布者、消息类型、订阅者和 token 用量，协作过程完全透明。

![共享消息池示意图](docs/images/message-pool.png)

### 5. 产物预览与下载

工程师产出的网页可在站内沙箱 iframe 中直接预览，支持刷新、新窗口打开、版本切换；文档与代码支持单文件下载，也支持 ZIP 打包下载。预览中出现的运行时报错会回传显示，便于继续让 Agent 修复。生成后还会自动执行预览自检（入口文件、内容完整性、本地资源引用、标签闭合），发现问题会自动让工程师修复一次。

![产物预览与下载示意图](docs/images/artifact-preview.png)

### 6. 角色自定义

除默认三角色外，可增删角色并编辑其名称、职责与订阅的消息类型，让团队结构适配不同任务。

![角色自定义示意图](docs/images/custom-roles.png)

### 7. 项目历史与对话迭代

每个项目就是一个持久化会话，保存全部对话、过程消息和各版本产物。回看历史项目的任一版本后继续发消息，即可在上一版基础上生成新版本（v2、v3…），产物面板可切换版本查看。

![项目历史示意图](docs/images/project-history.png)

### 8. 中断与续跑

运行中中断会真正取消后端正在进行的模型请求，已生成的消息和产物全部保留，之后可继续在当前版本上迭代，不会丢失上下文。

## 快速开始

### 方式一：一键启动脚本（推荐）

项目自带启动脚本，会自动分配端口并注入平台后端环境变量：

```bash
cd app
bash start_app_v2.sh
```

### 方式二：分别启动前后端

```bash
# 后端
cd app/backend
uvicorn main:app --host 0.0.0.0 --port 8000 --reload

# 前端（另开一个终端）
cd app/frontend
pnpm install
pnpm run dev
```

### 构建校验

```bash
cd app/frontend
pnpm run lint
pnpm run build
```

> 说明：数据库、登录、对象存储等能力由 Atoms Cloud 平台注入，本地运行时需要平台提供的后端环境变量。

## 模型配置

登录后进入「模型配置」页面，填写以下三项并点击「连通性测试」：

| 配置项 | 说明 | 示例（占位符） |
| --- | --- | --- |
| Base URL | OpenAI 兼容接口地址，通常以 `/v1` 结尾 | `https://api.example.com/v1` |
| 模型名 | 服务商文档中的模型标识 | `your-model-name` |
| API Key | 服务商控制台申请，仅保存在服务端 | `sk-xxxxxxxx` |

填写后点击「连通性测试」会在约 0.5 秒内返回结果；测试通过即可在「工作台」输入需求启动团队。

> 请使用你自己的服务商账号与 Key，不要在仓库或代码中硬编码任何真实密钥。

## 使用流程

1. 登录并完成模型配置。
2. 工作台输入一句话需求，启动角色团队。
3. 观察 SOP 流水线与消息池中的协作过程，随时可点击「停止任务」中断。
4. 在产物面板的「预览」页签中直接查看生成的网页，或切到「文件」页签查看 PRD、设计文档并下载 ZIP。
5. 继续发送消息（例如「增加暗色模式切换按钮」）即可生成新版本。
6. 在「项目历史」中回看任意历史项目并继续迭代。

## 常见问题

**Q：连通性测试失败怎么办？**

先确认 Base URL 是否以 `/v1` 结尾、模型名与服务商文档一致、Key 未过期且额度充足；再确认运行后端的机器能访问该接口地址（内网地址在本地通常不可达）。

**Q：模型生成的文档或代码被截断？**

单个步骤有输出长度上限（文档约 3500 token、代码约 6000 token），过长的需求可拆分成多次对话迭代，让 Agent 逐步补齐。

**Q：生成的前端产物能直接运行吗？**

产物是可直接打开的静态页面（HTML/CSS/JS），可在沙箱中预览并打包为 ZIP 下载；它是一个独立产物，不会自动替换本站点自身的代码。

**Q：页面上的「逐字输出」是实时流式返回吗？**

不是。模型结果返回后前端做逐字展示以提升过程可读性，并非真正的流式传输；单步请求有约 85 秒的超时上限。

**Q：API Key 会被上传到哪里？**

只保存在后端数据库，接口返回与日志中均脱敏（形如 `sk-****`），不会随产物或导出文件泄露。

**Q：任务运行到一半能停吗？**

可以。中断会真正取消后端正在进行的模型请求，已生成的消息与产物保留，之后可继续迭代。

## 安全说明

- 模型 API Key 只保存在服务端数据库，接口返回时脱敏，不写入日志。
- 仓库中不包含真实密钥，`.env` 已被 `.gitignore` 排除。
- 预览使用沙箱 iframe，脚本运行受限，不会访问站点的登录态。
